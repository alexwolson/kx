# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kaiserredux (KX) — a Hearts of Iron IV total-overhaul mod (a fork/expansion of Kaiserreich, `supported_version 1.19.*`). Everything is Paradox/Clausewitz script (`.txt`), the custom `l_english` localisation dialect (`.yml`), and image assets. ~88k tracked files, mostly PNG/TGA/DDS art. There is no build system, linter, or test suite: verification means loading the mod in HoI4. The mod's own debugging mechanism is the near-universal logging convention — every event `immediate`, focus `completion_reward`, and decision effect starts with `log = "[GetDateText]: [Root.GetName]: <what happened>"`, which is traced in the game's `game.log`. Replicate this line in any new content.

Navigation is grep-driven: identifiers are the join keys between directories, so `grep -r` for an id (e.g. a focus id, event namespace, `GFX_` name, or `TAG_` idea) is how you find all pieces of a feature.

- `descriptor.mod` is **gitignored on purpose** (its `path=` line is machine-specific; see Readme.txt for the install flow). Never commit it; don't assume it exists on a fresh clone.
- Git history carries no information (most commit messages are literally "a"). Use blame/diffs, not messages.

## replace_path: the rule that governs every edit

The local `descriptor.mod` lists ~88 `replace_path` directories (`events`, `history/countries`, `history/states`, `history/units`, `common/national_focus`, `common/ideas`, `common/country_tags`, `map/strategicregions`, `gfx/flags`, `portraits`, most of `common/`...). In those directories **vanilla is gone entirely** — nothing falls back to base game, and deleting a mod file deletes that content. Directories *not* listed (`localisation/`, `map/` root, `interface/`, `common/defines`, most of `gfx/`) **merge** with vanilla: a file with a vanilla filename silently replaces that whole vanilla file; new filenames add alongside. Check which regime a directory is in before adding, renaming, or deleting files there. Same rule for `common/on_actions`: new filenames merge additively (all hooks fire), but a vanilla-named file like `07_nsb_on_actions.txt` replaces the vanilla file wholesale.

## File formats — hard rules

- **Clausewitz script**: tab-indented, `#` comments, case-insensitive keys, whitespace around `=` inconsistent across files. Never reformat existing files; match local style.
- **Localisation `.yml` is NOT YAML.** Format: UTF-8 **with BOM**, first line `l_english:`, then `key:0 "value"` (`:0` version number optional). Values are single physical lines using `\n` and `\"`. Markup: `§Y...§!` color spans, `£GFX_icon` inline icons, `$key$` substitution/transclusion, `[Scope.GetName]` bracket commands. Never run a YAML parser or formatter on these files. Filenames must end `_l_english.yml`.
- **Line endings are inconsistent, and it is drift rather than a convention.** The index holds **7,114 LF vs 156 CRLF** files (plus one genuinely broken mixed file, `interface/KRR_companies.gfx`), even though `.gitattributes` has carried `* text=auto` since the very first commit — the CRLF files were almost certainly committed through the GitHub web UI, which bypasses normalization, and they persist because Git keeps whatever bytes are already in the index. Nevertheless, **check `git ls-files --eol <file>` before editing and preserve what is there**: rewriting a CRLF file as LF turns a one-line fix into a whole-file diff. Fixing this properly is a deliberate repo-wide change, not something to do in passing — see below.
- **`* text=auto` with no `eol=` is very likely the cause of open issue #123 (checksums differ between Linux and Windows).** With that setting, the ~7k LF-in-index files are converted to CRLF on checkout by Git for Windows (`core.autocrlf=true` is its default) but stay LF on Linux/macOS, so the files on disk differ byte-for-byte per platform and HoI4 hashes a different mod. A GitHub ZIP download exports index bytes verbatim and applies no conversion, so a ZIP user and a `git clone` user *on the same Windows machine* can also end up with different checksums — which matches the reporter's "other (not all) mods have matching checksums". The fix is `* text=auto eol=lf` plus a one-off `git add --renormalize .`. Note the consequence before doing it: it changes the mod's checksum for everyone, so it breaks multiplayer sync until all players update. Leave `*.csv text eol=crlf` alone — it is already explicit and deterministic across platforms.
- **Copy identifiers exactly, including typos.** Existing misspellings (`[GetDatext]`, `liberatarian` flag filenames) are load-bearing — "fixing" one side breaks the reference.
- The 91 **BOM-only empty** `.yml` files in `localisation/english/` (e.g. `state_names_l_english.yml`) intentionally blank vanilla/DLC loc files. Don't delete or populate them.

## Silent-failure gotchas

Nothing here throws an error. Each was verified against this repo or vanilla while fixing real bugs — check them before assuming script does what it reads like.

- **`NOT = { a b }` is NAND, not NOR.** It negates the implicit AND, so it passes whenever *any* child is false. To mean "neither", you must write `NOT = { OR = { a b } }` — which is exactly what Paradox does in vanilla (`common/national_focus/argentina.txt:1344`), and that `OR` would be redundant if bare `NOT` were already NOR. Multi-condition `NOT` blocks in this repo are frequently written as if they were NOR and are a standing source of triggers that fire when they shouldn't (`saf.85`/`saf.86` in `events/South_Africa.txt` are live examples). Conditions at the top level of a `trigger`/`limit` are ANDed, so adding a guard there is unambiguous — prefer that over editing an existing `NOT`.
- **A timed decision (`days_remove`) needs a `cancel_trigger`.** `available` and `target_trigger` only gate *starting* it; once running, the `remove_effect` fires regardless of how the world changed. Any decision that annexes, transfers or attacks a specific target needs an explicit `cancel_trigger` re-checking that target.
- **Grant building slots before queueing the building.** Within a state scope, `add_extra_state_shared_building_slots` must come *before* `add_building_construction` or the construction is silently dropped when the state is at capacity. Repo convention is slots-first by 1515 sites to 89. Only matters for buildings drawing on the shared pool (`industrial_complex`, `arms_factory`, `synthetic_refinery`, …); `infrastructure`, `dockyard`, `air_base` and `naval_base` have independent caps, so order is irrelevant for them.
- **An `ai_strategy` `id` lives in one of three different namespaces, decided by the strategy `type`.** Getting this wrong is the single easiest way to silently kill a strategy, and it has already caused a live regression (`9dcfcc0b`, reverted by PR #137).

  | `type` | `id` is a | source | example |
  |---|---|---|---|
  | `role_ratio`, `build_army` | role | `common/ai_templates/` | `armor_role`, `mountaineer` |
  | `template_prio` | sub_unit | `common/units/` | `mountaineers` |
  | `equipment_*`, `unit_ratio` | equipment archetype/category | `common/units/equipment/` | `armor`, `infantry` |

  The same word means different things per column — `mountaineer` is the role, `mountaineers` is the battalion, and both are correct in their own place. `armor` vs `armor_role` is the sharpest trap: the role is deliberately named `armor_role` *because* `armor` is the hardcoded equipment keyword, as the comment in `ai_templates/armour.txt` says. So `id = armor` is right under `equipment_production_factor` and wrong under `role_ratio`.

  `common/ai_templates` is `replace_path`, so only KX's six roles exist — `armor_role`, `hq_role`, `infantry`, `marine`, `mountaineer`, `suppression`. Vanilla's ~30 (`cavalry`, `motorized`, `garrison`, `militias`, `paratroopers`, …) are gone, deleted by `2ce9e89f59` (2024-11) without updating the per-country strategy files. Naval `role_ratio` ids (`naval_capital_bb`, `naval_screen`, …) are hardcoded engine roles and always valid. `kx-patchkit/role_audit.py` checks all of this.
- **on_action scopes** (documented in `common/on_actions/on_actions_global.txt`, worth re-checking per hook): `on_declare_war` — ROOT = aggressor, FROM = target, so a hook written only on ROOT misses the country being attacked, and it does not fire at all for call-to-arms. `on_war` — ROOT = the country entering a war; the reliable catch-all for "got into a war with X", vanilla uses it that way. `on_puppet` / `on_release_as_puppet` — ROOT = nation being puppeted, FROM = overlord.
- **Bloc membership (Mitteleuropa, Rostorg) is driven by the member ideas, not by on_actions.** An idea's `cancel` block removes it, `on_remove` then calls the teardown effect (`GER_remove_from_mitteleuropa`, `RUS_remove_from_rostorg`) which pops the membership array. So the place to add "you should leave the bloc when X" is usually the idea's `cancel`, not a new hook. Leader ideas may cascade — removing `RUS_moscow_accord_leader_*` dissolves the whole bloc.
- **`effect_tooltip = { ... }` is display-only.** Effects inside it are shown to the player but never execute; an option that "obviously" retires a leader may only be advertising it.
- **Minister localisation lives in `localisation/KR_Ministers_l_english.yml` with TAB-indented keys.** Grepping `^ *NAME:` reports a false "missing key". Use `grep "[[:space:]]NAME:"`. More generally: before adding any identifier, confirm it exists in *both* script and localisation, since a dangling reference produces no error — just a missing minister or a raw key on screen.
- **`create_country_leader` refuses a duplicate, so anything attached to the re-creation is silently dropped.** If a leader with that name already exists at that `ideology`, a second `create_country_leader` logs `already has an ideology X` and does nothing — including any `traits = { … }` on it. Norway had this for years: `norway.320` tried to give Tranmæl `NOR_socialist_organiser` and Eines `NOR_red_pressman` by re-creating them, and neither trait ever applied. Put characterizing traits on the **history-file** definition instead, which is how Haakon VII already works (`NOR_popular_king` is declared there across all five of his ideology entries) and is robust to the release path in `Annexations.txt` re-creating the same leaders. Note a *different* name at the same ideology legitimately replaces the leader, so that case does work.
- **`add_ideas` has two forms and mixing them fails silently.** `add_ideas = X` takes one name; `add_ideas = { X Y Z }` takes bare names. Writing `add_ideas = { add_ideas = X … }` adds nothing. When it follows `remove_all_ministers = yes` the country is left with an empty cabinet, which is exactly what happened to COR in `constate.6776` (PR #139).
- **Identifiers can contain apostrophes and hyphens**: `IRE_Eoin_O'Duffy_hog_pau`, `german-ukrainian_railways`, `MAF_Flandro-Wallonian_Influence`. A `[\w.]+`-style pattern truncates them, which breaks greps and tooling on *both* sides — the definition and the reference — so the identifier looks simultaneously missing and undefined.
- **Event namespaces can contain dots, and ids need not be numeric.** `kr.political.30` is namespace `kr.political`; `ausgleich.new.202` is `ausgleich.new`; `cend.conflict` has no number at all. Anything assuming `namespace.NUMBER` will mis-parse thousands of ids.
- **Reference case does not always match the definition.** 121 references differed from their definition only in letter case (`CAF_albert_gomes_for_syn` vs `CAF_Albert_Gomes_for_syn`, `alaska.101` vs the declared `Alaska` namespace). Whether these lookups are case-sensitive is unresolved, so the safe habit is simply to copy the definition's exact casing — that is a no-op if the engine is lenient and a fix if it isn't.
- **A prefix that looks like a typo may be a dead namespace.** `NATFRA_*` appears 83 times across 10 files and looks like a misspelling of `NFA_`, but only 8 of ~65 distinct tokens have an `NFA_` counterpart — the rest exist under neither. The result is that `NFA_remove_de_gaulle_military_ideas` removes ~30 ideas that do not exist and therefore does nothing. Before "fixing" a prefix, check how many of its tokens actually resolve under the replacement.
- **`id = <something>` alone on a line is usually a *reference*, not a definition.** Events are written `country_event = {` then `id = x` on the next line, so `grep "id = alaska.61"` finds callers and definitions alike and will convince you a dangling event exists when it doesn't — or that a real one is fine. A definition is a `country_event`/`news_event` block opening at **column 0**; anything indented is a call site. The same shape appears in decisions and `ai_strategy`. When checking whether something is defined, match the definition's own syntax (`^NAME = {` at the right depth), never the bare id.

## How a country is wired

A 3-letter TAG is the join key across ~10 directories. Verified end-to-end example: Alaska (ALA).

- **Tag registration**: `common/country_tags/kx_countries.txt` (`ALA = "countries/Alaska.txt"`); base-KR tags in `00_countries.txt`. Everything after `dynamic_tags = yes` in `zz_dynamic_countries.txt` is a temporary civil-war tag — never add normal tags there. Map colors come from `common/countries/kx_colors.txt` and `cosmetic.txt`, not the (3-line) country file.
- **History**: `history/countries/"ALA - Alaska.txt"` sets capital, tech, `set_politics`/`set_popularities`, adds starting ideas *and minister ideas*, schedules bootstrap events, and creates **all country leaders and generals inline** via `create_country_leader`/`create_field_marshal` with raw portrait paths (`gfx/leaders/ALA/*.png`). `load_oob = ALA_NAVY` → `history/units/ALA_NAVY.txt`.
- **Ministers are ideas, not characters** (KR convention): defined in the giant `common/ideas/_Ministers_ideas.txt` (~244k lines — grep, never read whole) and bundle files like `EMV_Ministers.txt`, keyed `TAG_Name_role_ideo` (roles `hog/for/eco/sec`; ideology suffixes `sli/sde/tot/syn/pau/npo/mli/...`). Government changes must call the scripted effect `remove_all_ministers = yes` before `add_ideas` of the new four, or old ministers stack. `common/characters/KX_<TAG>.txt` holds only the newer character system (scientists, some advisors); characters are a **global namespace** — the `TAG_` prefix is convention, not ownership.
- **Focus tree**: `common/national_focus/Alaska.txt`. Trees bind by **weight**, not name: `country = { factor = 0 modifier = { add = 10 tag = ALA } }` — forget the modifier and the country silently gets the generic tree. Shared branches via top-level `shared_focus = {}` blocks in `*_Shared.txt` files, pulled in with `shared_focus = <id>`.
- **National spirits**: `common/ideas/<Name>_ideas.txt`, all `allowed = { always = no }`, granted from history/focuses/events.
- **Events**: `events/` is flat, one file per country/arc plus shared systems. Each file declares `add_namespace` at the top (one file may declare many; **namespace ≠ filename** — find an event's file by grepping `add_namespace`). Ids `namespace.N` are grouped in loose thematic blocks; grep before picking a number. New events must be `is_triggered_only = yes` and fired from a focus/decision/on_action/scripted effect — MTTH events are reserved for hidden AI-steering (`events/AI.txt` pattern). An unwired event silently never fires.
- **Decisions**: `common/decisions/<Name>_decisions.txt` + custom categories in `common/decisions/categories/`, gated `allowed = { original_tag = TAG }` (evaluated once at startup; survives cosmetic tags and civil-war splits — the mod consistently prefers `original_tag` in `allowed`).
- **Balance of power**: `common/bop/TAG.txt` is inert until an effect runs `set_power_balance`; its UI appears only via the decision category named in its `decision_category`.
- **Cosmetic tags** (`set_cosmetic_tag = ALA_RED`) need no registration but need three parallel assets or you get unlocalized names/black flags: a color block in `common/countries/cosmetic.txt`, flags `gfx/flags/<COSTAG>_<ideology>.tga`, and per-ideology loc keys. Country display names are **always** per-ideology keys (`ALA_social_liberal:0`, plus `_ADJ`/`_DEF`) — there is no plain `TAG:` key.
- **Localisation for a country** (names, events `id.t`/`.d`/`.a` per option, focuses `<id>`+`<id>_desc`, ideas, decisions) lives in that country's single `localisation/KR_<Name>_l_english.yml`. Missing keys display raw. Option keys may legally point at other events' keys — grep before assuming a key is unused.

The 10 ideologies (`totalist, syndicalist, radical_socialist, social_democrat, social_liberal, market_liberal, social_conservative, authoritarian_democrat, paternal_autocrat, national_populist`) are defined in `common/ideologies/00_ideologies.txt` and appear everywhere: flag suffixes, popularity blocks, name keys, minister suffixes.

## Shared scripting framework

Underscore-prefixed files are the shared layer; `<Country>_scripted_effects.txt` etc. are per-country content.

- `common/scripted_effects/_useful_scripted_effects.txt` and `common/scripted_triggers/_useful_scripted_triggers.txt` are the core libraries (`remove_all_ministers`, `copy_government_of_ROOT`, `separate_peace_all_wars`, `has_socialist_government`, `is_actual_major`, region triggers like `is_russian_far_east`). Prefer these — and the `*_allowed` ideology gates in `KR_ideology_allowed.txt`, which encode dozens of per-tag exceptions — over raw `has_government` checks.
- Shared helpers come in **scope-variant suffixes** (`_ROOT/_PREV/_FROM`, e.g. `embargo_FROM`) because scope resolution is static: pick the variant matching your call site or it silently targets the wrong country.
- **Party popularity/coalitions have an API** (`_party_popularity_effects.txt`): set `ideology_change_var` then `change_ruling_party_popularity`, or the `increase/decrease_ruling_party_popularity_by_N` wrappers; coalitions via `coalition_partner_var` + `add_to_coalition`. Don't mutate popularity/ruling party raw in shared flows. Note `on_government_change` (in `on_actions_global.txt`) has global side effects (ends coalitions, recalls volunteers).
- **Do-not-edit headers**: `common/on_actions/on_actions_global.txt` ("check in the coding channel first" — country hooks belong in their own `on_actions_<Country>.txt` files) and `common/on_actions/_on_actions_arrays.txt` (only add/remove tags). Game-rule options are translated to global flags at startup in `KX_on_actions.txt` and checked as flags thereafter.
- **Annexation/release framework** is the flagship cross-directory system: adding a releasable nation touches, in lockstep, a `can_release_X` trigger in `common/scripted_triggers/Annexation_triggers_<region>.txt`, an `else_if` branch in `check_possible_annexations_<region>` (`Annexation_GUI_scripted_effects.txt` — branch order matters), a mission in `common/decisions/Annexation_decisions.txt`, state + `TAG.release_event` registration in `common/on_actions/on_actions_annexations.txt`, and the release event in `events/Annexations.txt`. `recheck_annexations` is debounced 7 days (`recheck_annexations_immediate` for same-tick).
- Meme/easter-egg tags are excluded from shared systems via `is_meme_mode_tag = no` — include the same guard in new global logic.
- Newer engine data plumbing: `common/script_constants/` (schema'd constants, `constant:` prefix), `common/collections/` (`collection:` prefix), `common/mtth/mtth_variables.txt` (`mtth:` prefix). Per its own documentation.md, reloading constants in-game requires also reloading every consuming script file.

## Graphics

Standard chain: image under `gfx/` → `spriteType` registration in a flat `interface/*.gfx` file → referenced by `GFX_*` name. All 292 `interface/*.gfx` files share **one global sprite namespace** — grep before naming. (`gfx/entities/*.gfx` are 3D-model definitions, not sprites.)

- **Full-name vs short-name is the #1 trap**: focuses use the full name (`icon = GFX_goal_X`); ideas/ministers use the short name with `GFX_idea_` auto-prepended (`picture = X`); events use the full name (`picture = GFX_report_event_X`). Wrong form silently shows the fallback sprite.
- **A focus icon is a three-part edit**: PNG in `gfx/interface/goals/`, base sprite in a `*_goals.gfx`, and a `GFX_<name>_shine` twin in the matching `*_goals_shine.gfx`. The shine files are machine-generated (header forbids manual edits; the generator tool isn't in this repo) — in practice, copy an existing shine block and substitute the texture path.
- **Flags bypass .gfx entirely**, resolved by filename from tag/cosmetic tag + ideology group: every flag needs **three** 32-bit TGAs — `gfx/flags/<name>.tga` (82×52), `medium/` (41×26), `small/` (11×7) — with ideology suffixes exactly matching the 10 ideology names.
- Leader/general portraits in history files are raw file paths (no .gfx entry); portraits used via `common/characters` or the `portraits/*.txt` random pools must be registered `GFX_Portrait_*` sprites (`interface/_random_portraits.gfx`, `_scientists_portraits.gfx`), typically with both large (`gfx/leaders/`) and `_small` (`gfx/interface/ministers/`) variants.
- Formats: PNG for nearly all mod content (focus icons, ideas, portraits, event pictures); TGA for flags; DDS mostly vanilla-style UI furniture.

## Map and world setup

The map is fully custom — **vanilla province/state ids are meaningless here**. `map/definition.csv` has ~16.1k provinces; `history/states/` has all 1,366 states; there is exactly **one bookmark** (`common/bookmarks/the_gathering_storm.txt`, 1936.1.1).

- State files (`history/states/<ID>-<Name>.txt`): the `id =` field is authoritative, the filename cosmetic (spacing is inconsistent). `history = {}` holds owner/controller/`add_core_of`/`add_claim_by`/victory points/buildings. VP, division `location =`, and building sub-block keys are **province** ids that must appear in that state's `provinces = {}`. No date-scoped blocks exist anywhere (single start date) — `1939.1.1 = {}` blocks are dead code.
- Bookmark per-country blocks are **selection-screen display only**; actual starting conditions live in `history/countries` + `history/states`. Every bookmark must end with `effect = { randomize_weather = <seed> }`.
- Air OOBs are DLC-forked: new countries with air forces need both `TAG_air_bba` and `TAG_air_legacy` unit files plus the `has_dlc = "By Blood Alone"` branch in the history file (pattern in `"GER - Germany.txt"`). DLC-conditional branches (`has_dlc = "No Step Back"` etc.) are standard boilerplate throughout history and effects. Dangling references (e.g. a `set_air_oob` with no matching file) are **silent** — always grep that a referenced OOB/GFX/loc key exists. This boilerplate is very often copy-pasted without the files: **94 tags currently call both `TAG_air_bba` and `TAG_air_legacy` while shipping neither**, and none of them has air units from any other source, so they start with no air force (issue #140). Copying a country file is the usual way this happens — check the OOBs exist before assuming the new country inherits an air force.
- `strategic_locations/strategic_locations.txt` defines per-province building-cap bonuses applied from state history as `strategic_state_location = { <location> = <provID> }` — note its own documentation.md shows a wrong effect name (`strategic_location`); copy from a real user like `history/states/698-Azores.txt`.
- Island states use the KX categories `zero_island/one_island/two_island` (which cap naval/air base levels); other categories are the number words `one`..`twelve` = building slots.
- `history/general/` is not generals — it generates generic advisors for all countries via `generate_character` templates.

## AI and country paths

- The "Custom Country Paths" game-rules system is the biggest cross-cutting feature: rules in `common/game_rules/game_rules_country_paths.txt` are consumed via `has_game_rule` in roughly two-thirds of focus/event files, and the AI is steered down the chosen path by `common/ai_strategy_plans/` (`hotb_strategy_plans.txt` for USA, `two_kr_strategy_plans.txt` for others). A new country path touches all four layers: rule + loc (`TWO_KR_game_rules_l_english.yml`) + `has_game_rule` gates + a strategy plan.
- Most minors have no `common/ai_strategy` file — their AI is driven in-tree via per-focus `ai_will_do` and per-event `ai_chance`.
- AI ship/equipment design has a battle-tested in-repo guide, `common/ai_equipment/_documentation_AI_ships_production_KR.info`, full of silent-failure gotchas (unlisted `target_variant` slots never filled; category-less modules like `ship_medium_battery` silently stop the AI building the hull; `role_ratio = 0` blocks production but not refits). Read it before touching `ai_equipment`.

## Naming conventions

- Filename prefixes mark provenance/subsystem, not one scheme: `KR_` = inherited Kaiserreich base, `KX_` = Kaiserredux originals, `FA_` = Africa content bundle, `BOTDE_` = Austria-Hungary/Danubian content, `EMV_` = a minister system bundle, `TWO_KR_`/`two_kr_`/`hotb_` = the country-path game-rules system. Most files have no prefix and are named for the country/arc. Don't invent acronym expansions.
- Every country-scoped identifier is `TAG_`-prefixed (ideas, focuses, flags, bop ids, GFX names). Per-country files are keyed by country *name* (`Alaska.txt`, `Alaska_decisions.txt`, `KR_Alaska_l_english.yml`) except where the engine demands the TAG (`"ALA - Alaska.txt"`, `common/bop/ALA.txt`, `history/units/ALA_*.txt`, `gfx/flags/`, `gfx/leaders/ALA/`).
- New mod localisation goes in the root `localisation/` dir. `localisation/english/` holds vanilla/DLC-filename overrides; `localisation/replace/` (e.g. `KR_Vanilla_Override_l_english.yml`) force-replaces individual vanilla keys. The tier changes the override semantics — pick deliberately.

## Audit tooling

`~/code/personal/kx-patchkit/` (outside this repo, so it never appears in diffs) holds scripts for the silent-failure classes above. Run these before assuming a reference works:

- `dangling.py` — references to ideas, event ids, OOB files and leader traits that are never defined. `--validate` first.
- `role_audit.py` — `ai_strategy` ids against the three namespaces above.
- `patch_status.py`, `sync.sh` — fork maintenance against upstream.

**Validate any audit before believing its output.** Every one of these scripts was wrong on its first run in a way that looked like findings — 1641 phantom missing events from assuming `namespace.NUMBER`, 871 phantom ideas from a tokenizer that split on apostrophes, 45 "dangling" AI roles from conflating two namespaces. A high resolve rate says the extractor is sane; it says nothing about whether the residual failures are real, so spot-check those individually against a known-good control.

## In-repo documentation

Authored references sit inside the directory they document; read them before editing that system: `common/script_constants/documentation.md`, `common/doctrines/subdoctrines/_documentation.md` (the custom grand-doctrine/subdoctrine system), `common/operations/_documentation.md` (note: in operation scope `FROM` = target, `ROOT` = origin), `common/ai_equipment/_documentation*.info`, `common/units/equipment/_documentation.info` (`fixed_` slot-prefix rule), `common/units/names_ships/_00_readme.txt` (duplicate ship names silently delete ships), `common/map_modes/documentation.txt`, `common/military_industrial_organization/*/documentation.info`, `strategic_locations/documentation.md` (stale effect name — see above).
